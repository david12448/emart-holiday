# 마트 휴무일 시스템 구현 기록

이 문서는 신규 브랜드 추가 및 유지보수 과정에서 확인한 시행착오, 설계 판단, 해결 방법을 기록합니다.
기존 동작을 임의로 변경하지 않고 현재 공개 저장소의 데이터/UI 계약을 우선 유지합니다.

## 2026-10-06 — 코스트코 작업 사전 조사

### 현재 구조 확인

- 이마트 계열은 `fetch_emart_family.py`에서 공식 휴점일 API를 수집합니다.
- 공개 데이터는 브랜드별 `data/<brand>/` 아래에 두고, 현재 데이터/아카이브/최신 스냅샷/변경 상태를 분리합니다.
- 프런트엔드는 `assets/holiday-app.js`, `assets/holiday.css`를 공통으로 사용하고 각 브랜드의 `index.html`은 `window.MART_CONFIG`로 데이터 위치와 표시 정보를 주입합니다.
- 롯데마트는 `data/lotte/lottemart/stores.json`을 공개 데이터 계약으로 사용하며 `data/lotte/change_status.json`에서 롯데 계열 변경 상태를 공유합니다.
- 롯데 데이터 생성은 공개 저장소 내부 수집기가 아니라 별도의 비공개 `retail-store-source`에서 공개 저장소로 배포되는 구조임을 `lotte/index.html` 주석에서 확인했습니다.

### 코스트코 조사 결과

- 현재 공개 저장소에는 Costco 관련 디렉터리/코드가 없습니다. 따라서 기존 파일을 수정하기보다 신규 브랜드 어댑터로 추가하는 것이 현재 구조와 가장 잘 맞습니다.
- 코스트코 코리아 공식 사이트는 매장 안내에서 영업시간·휴무일·위치를 제공한다고 명시합니다.
- 공식 사이트의 로드쇼 페이지에서도 전국 매장 목록을 확인할 수 있습니다.
- 따라서 첫 구현에서는 제3자 휴무일 자료나 법정 의무휴업일을 추정하여 생성하지 않고, 코스트코 공식 매장 정보를 원본(source of truth)으로 사용해야 합니다.

### 시행착오 / 주의사항

1. GitHub 저장소에서 `costco`를 코드 검색했지만 결과가 없었습니다.
   - 결론: 미완성 Costco 코드를 이어 붙이는 단계가 아니라 기존 이마트/롯데 계약을 분석한 뒤 신규 브랜드를 추가하는 단계입니다.

2. GitHub Actions 전체 workflow 목록을 일반 fetch 경로로 읽으려 했으나 connector 허용 endpoint 제약으로 실패했습니다.
   - 해결: 필요한 workflow 파일을 저장소 경로에서 직접 읽는 방식으로 확인합니다.
   - 이 실패는 프로젝트 코드 문제와 무관합니다.

3. 코스트코 휴무일을 단순히 '매월 둘째/넷째 일요일' 같은 규칙으로 생성하면 지자체별 예외 및 점포별 일정 변경을 놓칠 수 있습니다.
   - 결정: 공식 점포 데이터에서 실제 휴무일을 가져올 수 있는 경로를 먼저 확정한 뒤 구현합니다.

### 2026-10-06 — 공식 휴무일 페이지 구조 확인 및 1차 구현

#### 확인 결과

- 공식 휴무일 페이지: `https://www.costco.co.kr/closedSchedule`
- 공식 전국 매장 목록은 로드쇼 페이지에서 20개 매장으로 확인했습니다.
- 휴무일 페이지의 핵심 일정은 구조화된 HTML 표가 아니라 Contentstack 이미지 한 장으로 게시됩니다.
- 검색/캐시 환경에서 확인된 이미지 파일명에는 연월 정보가 포함되어 있어 원본 이미지 교체 여부 자체는 자동 감지할 수 있습니다.

#### 방향 수정

처음에는 공식 휴무일 페이지의 HTML/API에서 날짜 배열을 바로 가져오는 방식을 기대했지만,
현재 확인된 공개 페이지는 이미지 중심이라 날짜를 안정적으로 파싱할 구조화 데이터가 노출되지 않았습니다.

따라서 다음처럼 두 단계를 분리합니다.

1. **공식 원본 감시**
   - `fetch_costco_source.py`가 공식 `closedSchedule` 페이지에서 휴무일 이미지를 찾습니다.
   - 이미지 URL/해시/파일명의 연월을 `data/costco/source_state.json`에 기록합니다.
   - 공식 이미지가 바뀌면 원본 변경을 탐지할 수 있습니다.

2. **구조화 휴무일 데이터**
   - `data/costco/stores.json`은 공통 UI가 바로 사용할 수 있는 점포별 날짜 배열을 유지합니다.
   - 이미지에서 날짜를 자동 확정하기 전까지는 검증된 월 데이터만 넣습니다.
   - OCR 결과를 무조건 신뢰하여 자동 배포하는 구조는 채택하지 않습니다.

#### 시행착오

4. 로드쇼 행사 구간의 빈 날짜를 휴무일로 역추정하는 방법을 검토했습니다.
   - 대부분 점포는 일요일 휴무와 행사 구간 경계가 겹쳐 보이지만,
     일산/울산처럼 수요일 휴무가 있는 점포는 행사 기간이 휴무일을 가로질러 표시됩니다.
   - 결론: 로드쇼 날짜의 공백을 휴무일 데이터로 사용하는 것은 신뢰할 수 없습니다.

5. 공식 휴무일 페이지를 검색 인덱스에서 열었을 때 과거 월 이미지가 반환되는 경우가 있었습니다.
   - 원인: 검색/웹 캐시와 실제 사이트 갱신 시점이 다를 수 있습니다.
   - 결론: 자동화는 검색 결과가 아니라 GitHub Actions에서 공식 URL을 직접 요청해야 합니다.

6. 2026년 10월 1차 데이터는 현재 월 일정의 UI/스키마 검증용으로 `feature/costco` 브랜치에만 넣었습니다.
   - 다수 점포: 10/11, 10/25
   - 대구/대구 혁신도시: 10/12, 10/26
   - 일산: 10/14, 10/28
   - 울산: 10/14, 10/25
   - 이 데이터는 최근 월 자료와 기존 공식 패턴을 교차 확인한 **검증 중 데이터**이며, `main` 병합 전 공식 원본과 다시 확인합니다.

#### 현재 추가된 파일

- 처음에는 `workflow_dispatch`만 사용하고, 공식 원본 감시가 안정적인 것을 확인한 뒤 정기 스케줄을 켭니다.
- 기존 이마트/롯데 파일은 수정하지 않습니다.

#### 자동화 시행착오

7. 공식 원본 감시 workflow를 테스트하는 중 한 번 `git push`가 `fetch first`로 거절되었습니다.
   - 원인: 기능 브랜치에 연속 커밋이 들어오는 동안 먼저 시작한 Actions 실행이 오래된 HEAD에서 새 상태 파일을 커밋한 뒤 push하려 했기 때문입니다.
   - 공식 페이지 수집/이미지 탐지는 정상 성공했고 push 단계만 실패했습니다.
   - 이후 최신 HEAD에서 재실행한 workflow는 정상 완료했습니다.
   - 정기 자동화를 켜기 전에는 동시 실행 제어(`concurrency`) 또는 push 전 최신 브랜치 반영 전략을 넣어 같은 충돌을 방지할 예정입니다.

8. `store-finder` HTML의 script 주소를 처음 분석할 때 페이지 URL을 기준으로 상대경로를 조합했습니다.
   - 실제 HTML에는 `<base href="/spartacus/assets/">`가 있어 JS 번들의 기준 경로가 다릅니다.
   - 첫 진단 결과의 `/main-*.js` 주소는 잘못된 조합이었습니다.
   - 수정 후 `/spartacus/assets/main-*.js`를 기준으로 번들을 분석하고 있습니다.
